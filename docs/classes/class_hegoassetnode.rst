HEGoAssetNode
=============

**Inherits:** :ref:`HEGoTransformableInputReceiverNode<class_HEGoTransformableInputReceiverNode>` **<** :ref:`HEGoTransformableNode<class_HEGoTransformableNode>` **<** :ref:`HEGoBaseNode<class_HEGoBaseNode>` **<** :ref:`HEGoTrackableNode<class_HEGoTrackableNode>` **<** ``RefCounted``

Represents an instantiated Houdini Digital Asset (HDA) node.

.. rst-class:: classref-introduction-group

Description
-----------

Use this class to instantiate an HDA by operator name, set parameters, cook, and fetch output data.



Call :ref:`HEGoBaseNode.instantiate()<class_HEGoBaseNode_method_instantiate>` after assigning :ref:`op_name<class_HEGoAssetNode_property_op_name>`. Most data-access methods require a valid instantiated node; when called before instantiation they log an error and return a failed task.



All methods that interact with Houdini Engine return an :ref:`HEGoTask<class_HEGoTask>`. Await the task to get the result, through the node's :ref:`HEGoAssetAgent<class_HEGoAssetAgent>`, called ``hego`` in every example here:

::

    var task = asset_node.cook()
    var result = await agent.task(task)



\ :ref:`fetch_points()<class_HEGoAssetNode_method_fetch_points>` expects a resource compatible with ``HEGoFetchPointsConfig``. :ref:`fetch_surfaces()<class_HEGoAssetNode_method_fetch_surfaces>` expects a resource compatible with ``HEGoFetchSurfacesConfig``.

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **cook**\ (\ ) :ref:`🔗<class_HEGoAssetNode_method_cook>`

Submits a cook task for this asset node.



Returns an :ref:`HEGoTask<class_HEGoTask>` that completes with ``0`` once the cook has finished, and that **fails** when Houdini refuses to start the cook or the cook comes back with fatal errors. Awaiting it therefore gives ``null`` on either kind of failure, which is what a script should check before reading the output.



A cook that finishes with non-fatal errors succeeds: Houdini reports those as warnings and the geometry is still usable.

.. _class_HEGoAssetNode_method_fetch_cop_image:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **fetch_cop_image**\ (\ cop_path\: ``String`` = "", output_name\: ``String`` = ""\ ) :ref:`🔗<class_HEGoAssetNode_method_fetch_cop_image>`

Renders a Copernicus layer and returns its pixels as an ``Image``. A relative ``cop_path`` starts at this HDA instance. An absolute Houdini node path starts at the session root. An empty path selects the asset itself and is valid for a COP HDA. Pass the output connector's name in ``output_name``, or leave it empty to select connector zero.



The task evaluates the requested COP branch independently of SOP output geometry. It returns a top-origin, linear float32 image in ``FORMAT_RF``, ``FORMAT_RGF``, ``FORMAT_RGBF``, or ``FORMAT_RGBAF`` according to channel count. Integer ID layers fail because float32 cannot preserve all IDs. Invalid paths, output names, and non-image outputs also fail the task.

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **fetch_curves**\ (\ read_prim_attribs\: ``PackedStringArray`` = PackedStringArray(), read_point_attribs\: ``PackedStringArray`` = PackedStringArray()\ ) :ref:`🔗<class_HEGoAssetNode_method_fetch_curves>`

Submits a task to fetch all curve parts from the cooked asset.



The task result is an ``Array`` of ``Dictionary`` entries. Each curve entry contains:

\ ``type``: curve type, one of ``CURVE_TYPE_BEZIER``, ``CURVE_TYPE_NURBS``, or ``CURVE_TYPE_LINEAR``.

\ ``order``: curve order.

\ ``positions``: ``PackedVector3Array`` of control point positions for this curve.

\ ``knots``: ``PackedFloat32Array`` of knot values, present only when the curve has knots.

\ ``prim_attribs``: ``Array`` of {``name``, ``value``} dictionaries for each attribute listed in ``read_prim_attribs``.

\ ``point_attribs``: ``Array`` of {``name``, ``value``} dictionaries for each attribute listed in ``read_point_attribs``.

\ ``is_closed``: A boolean indicating whether the curve is closed.



The task result is an empty array when the node is not instantiated, the session is invalid, or geometry cannot be read.

.. _class_HEGoAssetNode_method_fetch_points:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **fetch_points**\ (\ fetch_point_config\: ``Resource``\ ) :ref:`🔗<class_HEGoAssetNode_method_fetch_points>`

**Deprecated:** Use :ref:`get_point_output()<class_HEGoAssetNode_method_get_point_output>` instead. Fetch configs are kept only so existing projects can move across.

Submits a task to fetch point data using a point-fetch configuration resource.



\ **Deprecated.** :ref:`get_point_output()<class_HEGoAssetNode_method_get_point_output>` does the same thing from code, decides at runtime, and keeps the attribute names next to the code that reads them. Both share one implementation and one per-cook cache, so results are identical.



Config fields are interpreted as follows:

\ ``filter_attribs`` and ``filter_attrib_values``: paired by index; a point is kept only if all ``point_attr == filter_value`` checks pass.

\ ``filter_attribs`` and ``filter_attrib_values`` should have the same length.

\ ``read_attribs``: extra point attributes to fetch at leaf level (in addition to ``P``, which is always included).

\ ``split_attribs``: point attributes used to build nested dictionary groups.



The method reads from the display mesh part of the cooked node.



The task result is a ``Dictionary`` with the following structure:

If ``split_attribs`` is empty, the result is a flat dictionary with leaf keys.

If ``split_attribs`` is non-empty, each split attribute adds one nesting level keyed by that attribute's value.

Leaf dictionaries contain:

\ ``ids``: filtered point indices in the source point array.

\ ``P``: ``Array`` of ``Vector3`` positions.

Additional keys from ``read_attribs``, each mapped to an ``Array`` aligned with ``ids``.



Returns an empty dictionary when no points pass filters, when no mesh part exists, or when geometry query fails.

.. _class_HEGoAssetNode_method_get_surface_output:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **get_surface_output**\ (\ point_attribs\: ``PackedStringArray`` = PackedStringArray(), preload_attribs\: ``PackedStringArray`` = PackedStringArray(), custom_attribs\: ``PackedStringArray`` = PackedStringArray()\ ) :ref:`🔗<class_HEGoAssetNode_method_get_surface_output>`

Submits a task returning a :ref:`HEGoSurfaceOutput<class_HEGoSurfaceOutput>`: the cooked surfaces, read and split from code rather than through a fetch configuration.



\ ``point_attribs`` names which of ``N``, ``Cd``, ``uv``, ``uv2`` and ``tangents`` to read; ``P`` always comes along. ``preload_attribs`` are primitive attributes, loaded while the task runs so the queries afterwards need no further await:

::

    var output = await agent.task(asset_node.get_surface_output(["N", "uv"], ["hego_material"]))
    for material in output.split_by("hego_material"):
        var surface = by_material[material].get_surface()



\ ``custom_attribs`` names up to four point attributes, in channel order, that each surface carries as ``Mesh.ARRAY_CUSTOM0`` to ``Mesh.ARRAY_CUSTOM3``, packed to RGBA float per vertex (float or int, tuple size 1 to 4; missing components are 0). A blank name, or an attribute the cook does not have, leaves that channel out. Surfaces with custom channels also hold ``custom_format_flags``, the flags argument ``ArrayMesh.add_surface_from_arrays()`` needs to add them; :ref:`HEGoMeshOutput.build_array_mesh()<class_HEGoMeshOutput_method_build_array_mesh>` passes it.



Attribute values are cached per cook and shared with :ref:`fetch_surfaces()<class_HEGoAssetNode_method_fetch_surfaces>` and :ref:`get_point_output()<class_HEGoAssetNode_method_get_point_output>`.

.. _class_HEGoAssetNode_method_fetch_surfaces:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **fetch_surfaces**\ (\ fetch_surface_config\: ``Resource``\ ) :ref:`🔗<class_HEGoAssetNode_method_fetch_surfaces>`

**Deprecated:** Use :ref:`get_surface_output()<class_HEGoAssetNode_method_get_surface_output>` instead. Fetch configs are kept only so existing projects can move across.

Submits a task to fetch surface data using a surface-fetch configuration resource.



\ **Deprecated.** :ref:`get_surface_output()<class_HEGoAssetNode_method_get_surface_output>` does the same thing from code. Both share one implementation and one per-cook cache, so results are identical.



Config fields are interpreted as follows:

\ ``normal``, ``color``, ``uv``, ``uv2``, ``tangents``: toggles for point-derived channels included in generated Godot surface arrays.

\ ``custom_attribs``: up to four point attributes exported as ``ARRAY_CUSTOM0..3`` (RGBA float), as in :ref:`get_surface_output()<class_HEGoAssetNode_method_get_surface_output>`.

\ ``read_attribs``, ``filter_attribs``, ``filter_attrib_values``, ``split_attribs``: primitive-attribute lists used for metadata readback, filtering, and grouping.

\ ``filter_attribs`` and ``filter_attrib_values`` are paired by index.

\ ``filter_attribs`` and ``filter_attrib_values`` should have the same length.



The method reads the display mesh part.



The task result is a ``Dictionary`` with the following structure:

If ``split_attribs`` is empty, the root is a single leaf dictionary.

If ``split_attribs`` is non-empty, result is nested by split attribute values.

Each leaf contains:

\ ``surface_array``: a Godot ``Mesh.ARRAY_MAX``-sized array usable with ``ArrayMesh.add_surface_from_arrays()``, including at minimum vertices and indices; optional channels are present depending on config and source attributes.

\ ``ids``: filtered primitive ids local to the current filtered set.

Any primitive attributes requested through ``read_attribs``, each as an ``Array`` aligned with ``ids``.



Returns an empty dictionary when no mesh part exists, no faces are available, no elements pass filters, or when geometry query fails.

.. _class_HEGoAssetNode_method_get_parms_dict:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **get_parms_dict**\ (\ ) :ref:`🔗<class_HEGoAssetNode_method_get_parms_dict>`

Reads the live Houdini interface. The task returns a ``Dictionary`` keyed by visible top-level parameter name. Folder contents are under ``children``. Each ``instances`` entry holds the child descriptors of one multiparm or ramp key.



Each descriptor includes ``type``, ``script_type``, ``size``, ``visible``, ``disabled``, UI and hard range flags and bounds. ``values`` holds evaluated components. String and path controls also expose authored ``raw_values``. Menus supply ``choice_list_type``, ``use_menu_item_token_as_value`` and, when populated, ``choices`` with each option's label and token.



The ``help`` string contains the first paragraph of the matching entry in the asset's embedded parameter documentation. Houdini wiki entries match by ``#id``, including multiparm template names. An entry without an ID can match a unique parameter label. If no entry matches, the string contains the parameter template's explicit help, which can be empty. See :ref:`get_help_page()<class_HEGoAssetNode_method_get_help_page>` for the complete document.



A folder list identifies its consecutive sibling folders with ``folder_ids``. Radio selection is the single integer in ``values``. Ordinary multiparms expose ``multiparm_style``, ramps expose ``ramp_type``, and instance children expose ``template_name``. For node parameters ``node_id`` is the current session's resolved target or ``-1``. Read the descriptors again after a structural edit, parameter callback, cook or asset rebuild. A HAPI read error fails the task.

:ref:`HEGoTask<class_HEGoTask>` **set_node_parm**\ (\ parm_name\: ``String``, source\: :ref:`HEGoBaseNode<class_HEGoBaseNode>` = null\ ) :ref:`🔗<class_HEGoAssetNode_method_set_node_parm>`

Binds a compatible, instantiated ``source`` to a single Houdini node-reference parameter. Pass ``null`` to clear the reference. A successful task returns ``0``. Setting the current binding again skips the write. An incompatible source, stale session or rejected operation fails the task. Reapply a durable source reference after an asset or session rebuild. Operator-path lists use the text form of :ref:`set_parm()<class_HEGoAssetNode_method_set_parm>`.

.. _class_HEGoAssetNode_method_set_parm:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **set_parm**\ (\ parm_name\: ``String``, value\: ``Variant``\ ) :ref:`🔗<class_HEGoAssetNode_method_set_parm>`

Sets a parameter by its Houdini name. Use a number for a scalar, a matching Godot vector for numeric tuples of two to four components, or a typed packed numeric array for any numeric tuple. The element count must match the declared tuple. Floats must be finite, integers must fit int32, and integer inputs to float storage must be exactly representable. Houdini's hard limits apply.



Toggles also accept a ``bool``. RGB and RGBA controls accept ``Color`` or a matching vector. RGB uses the first three channels. Use a ``String`` for a scalar string, authored file path or literal Houdini node path, and a ``PackedStringArray`` for a string tuple. To select a radio folder, pass its zero-based tab index. Integer writes to a button invoke its callback.



::

    await agent.task(asset.set_parm("rgb", Color(2.0, 0.5, 0.1)))
    await agent.task(asset.set_parm("words", PackedStringArray(["east", "west"])))

A successful task returns ``0``. Await the task before cooking or saving the result.

.. _class_HEGoAssetNode_method_set_parms_batch:

.. rst-class:: classref-method

:ref:`HEGoTask<class_HEGoTask>` **set_parms_batch**\ (\ parms\: ``Dictionary``\ ) :ref:`🔗<class_HEGoAssetNode_method_set_parms_batch>`

Submits one scheduled task for the parameter names and values in ``parms``. Keys may be ``String`` or ``StringName``. Value rules match :ref:`set_parm()<class_HEGoAssetNode_method_set_parm>`. The task captures the input, validates the whole batch, then resolves each live parameter again before writing it. Invalid input fails before the first write. If Houdini rejects a later write or a callback changes the layout, earlier writes may have taken effect. Read :ref:`get_parms_dict()<class_HEGoAssetNode_method_get_parms_dict>` before retrying.
