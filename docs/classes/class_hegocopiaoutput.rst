HEGoCopiaOutput
===============

**Inherits:** :ref:`HEGoOutputHandler<class_HEGoOutputHandler>` **<** ``RefCounted``

Writes a cook's points into a Copia store, on every cook of any HEGo node whose output

 carries them: the panel's Recook, a Session Sync update and a batch cook() all do the same.

.. rst-class:: classref-introduction-group

Description
-----------

HEGo finds this handler because it extends :ref:`HEGoOutputHandler<class_HEGoOutputHandler>`; neither HEGo nor Copia

 names the other. It acts on points with a ``hegocopia_object`` or a

 ``hegocopia_clear`` point attribute (the table is in docs/copia/houdini.md):

 

::


    hegocopia_object  string  path of a CopiaObject (or a Mesh); non-empty = an instance
    P, orient or N + up, scale, pscale                    the transform
    Cd, hegocopia_custom (+ hegocopia_custom_w)           optional colour and custom data
    hegocopia_keep    float   optional density priority 0..1
    hegocopia_set     string  set to write into; blank = default
    hegocopia_store   string  node path of the CopiaStore3D from the scene root; blank = the only one
    hegocopia_clear   int     1 = a clear point: empties set hegocopia_set in cell hegocopia_cell
    hegocopia_cell    string  "cx_cz", on clear points only



 

 Within one cook, clears are applied first and instances added after, per store. Nothing is

 cleared implicitly. One cook may write several sets and several stores.

 

 Options, from the host's metadata ``hegocopia`` and the cook state key

 ``hegocopia_options`` (a cook extension's cook_prepare can set it), the later one

 winning per key: ``extra_attributes`` (``PackedStringArray``), point attributes that

 are loaded too and stored as pass-through columns.

 

 The result is left in the cook state under ``hegocopia``:

 ``{stores: {path: result}, errors, warnings, point_count, clear_count, skipped_count}``\ 

 where each result is what :ref:`write_attributes()<class_HEGoCopiaOutput_method_write_attributes>` returns.

.. rst-class:: classref-method

``Dictionary`` **write_routes**\ (\ host\: ``Node``, routes\: ``Dictionary``, options\: ``Dictionary`` = {}\ ) |static| :ref:`🔗<class_HEGoCopiaOutput_method_write_routes>`

What :ref:`handle()<class_HEGoCopiaOutput_method_handle>` does with a cook's points once they are read: ``routes`` maps each

 ``hegocopia_store`` value to the attributes of the points that carry it (as

 :ref:`write_attributes()<class_HEGoCopiaOutput_method_write_attributes>` takes them), and ``options`` are the cook's options

 (:ref:`options_of()<class_HEGoCopiaOutput_method_options_of>`). Store paths are resolved first and the points of every path that

 names the same store are written in one call, so a blank path and the store's own path (the

 spawned points and the clear points of the documented pattern) clear before they spawn.

 Returns the report the handler leaves in the cook state:

 ``{stores: {path: result}, errors, warnings, point_count, clear_count, skipped_count}``.

``Dictionary`` **split_routes**\ (\ columns\: ``Dictionary``\ ) |static| :ref:`🔗<class_HEGoCopiaOutput_method_split_routes>`

 routes :ref:`write_routes()<class_HEGoCopiaOutput_method_write_routes>` takes, by ``hegocopia_store``: points without a store

.. _class_HEGoCopiaOutput_method_write_attributes:

.. rst-class:: classref-method

``Dictionary`` **write_attributes**\ (\ attributes\: ``Dictionary``, store\: ``Node``, options\: ``Dictionary`` = {}\ ) |static| :ref:`🔗<class_HEGoCopiaOutput_method_write_attributes>`

Writes the points in ``attributes`` into ``store``:

 ``{name: one value per point}`` as HEGo delivers them (plain Arrays, ``null``\ 

 where a point has no value; packed arrays work too), under the ``hegocopia_`` names above.

 

 Clear points are applied first, then the instances added. ``options``:

 ``extra`` (``PackedStringArray``), the names of attributes stored as pass-through

 columns. This is also the entry point for a cook extension that reads its points itself.

 

 Returns ``{ok, errors, point_count, clear_count, skipped_count, write}``. ``ok``\ 

 says the store took what there was to write (nothing to write is ok); ``errors``\ 

 also lists what the conversion skipped or ignored, so it can be non-empty when ok.

 ``write`` is ``CopiaStore3D.write()``'s result, empty when nothing was written.

``Dictionary`` **resolve_store**\ (\ host\: ``Node``, path\: ``String``\ ) |static| :ref:`🔗<class_HEGoCopiaOutput_method_resolve_store>`

Like :ref:`find_store()<class_HEGoCopiaOutput_method_find_store>`, with the reason when there is none: returns

 scene root (:ref:`scene_root()<class_HEGoCopiaOutput_method_scene_root>`).

 path). A blank one means the only ``CopiaStore3D`` of the scene: none, or several,

 is an error.
